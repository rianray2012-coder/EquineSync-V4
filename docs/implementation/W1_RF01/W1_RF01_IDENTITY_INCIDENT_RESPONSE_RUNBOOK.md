# W1-RF01 Identity Incident Response Runbook

1. Classify suspected credential theft, role elevation, token replay, cross-tenant access, recovery abuse, admin misuse, or identity-data corruption.
2. Preserve request, audit, token-family, actor, context, policy, and before/after evidence without exposing secrets.
3. Use separately authorized containment: account/session revocation, role/grant suspension, feature disable, or environment isolation.
4. Do not merge, delete, rewrite, or adjudicate identity during containment.
5. Assess affected barns, horses, minors, providers, records, payments, and external projections.
6. Notify only through approved communication and legal/privacy governance.
7. Restore access through verified authority and permission recalculation.
8. Reconcile audit gaps, rotate secrets only under explicit authority, and document root cause.
9. Require founder/security approval for production re-enable after a P0/P1 event.

This planning runbook does not itself authorize any containment action.
