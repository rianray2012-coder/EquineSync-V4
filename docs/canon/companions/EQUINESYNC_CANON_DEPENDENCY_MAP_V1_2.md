# 1. Purpose

This Map answers three constitutional questions: What must exist first?
What must be read together? What must be revalidated when a governing
artifact changes? It organizes the EquineSync canon into dependency
layers, identifies direct upstream prerequisites and mandatory co-review
overlays, records high-impact change propagation, and provides
implementation sequencing guidance without converting the map itself
into substantive authority.

The Map is interpretive and navigational. It does not create rights,
duties, permissions, adoption, lock, implementation authority,
production authority, provider activation, or public-launch authority.
The active version and lifecycle posture of every referenced family must
be resolved through the Controlled Canon Index and founder evidence.

# 2. Dependency Semantics

- Upstream prerequisite: a downstream artifact cannot be safely
  interpreted, amended, or implemented until the upstream rule is
  resolved.

- Protective constraint: a privacy, safeguarding, security, welfare,
  evidentiary, or permission rule that can narrow or block downstream
  action without taking ownership of the underlying subject.

- Evidence dependency: the record, audit, notice, or decision evidence
  required to prove that the governing rule was applied.

- Interpretive dependency: a registry, vocabulary, authority,
  cross-reference, or dependency artifact used to locate and reconcile
  substantive canon.

- Execution dependency: a required governance input to implementation
  planning, technical specification, testing, release, migration, or
  runtime activation.

- Coupled review: two canons must be reviewed together, but neither
  gains authority to amend the other.

> Founder-designated version exception: the Security Foundational Models
> V1.0 package is the controlling security-foundational package within
> its reconciled scope until expressly superseded. Higher-numbered
> security-family references do not displace the package by number
> alone.

| **Arrow rule: dependency arrows run from upstream prerequisite to downstream dependent. A cross-reference or dependency does not transfer subject-matter ownership.** |
|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------|

# 9. Dependency and Cycle-Control Rules

- A lower layer may implement a higher layer but may not amend, waive,
  contradict, or broaden it.

- A protective overlay may narrow or block action without becoming the
  primary subject-matter owner.

- Where two artifacts appear mutually dependent, separate the
  relationship into subject ownership, protective constraint, evidence,
  and execution before treating it as a cycle.

- True circular authority is prohibited. Unresolved cycles must enter
  controlled reconciliation before adoption, implementation, migration,
  or activation.

- A database field, route, role label, user interface, provider feature,
  model output, operational practice, or existing code path is never an
  upstream constitutional authority.

- A change to an upstream canon triggers review, not automatic
  amendment, of every mapped downstream family.

- The newest-version rule resolves to the active substantive successor
  supported by lifecycle evidence. A filename or version suffix alone is
  insufficient.

- Implementation and production remain separate gates. A complete
  dependency chain does not itself authorize execution.

# 10. Maintenance Triggers

- A canon is added, adopted, locked, superseded, renamed, split, merged,
  or retired.

- The Authority Matrix changes primary ownership or precedence for a
  subject.

- The Cross Reference Index adds or removes a mandatory reading set.

- A definition changes in a way that affects a dependency boundary.

- An RF identifies a new blocking prerequisite, unresolved collision, or
  implementation dependency.

- A release, migration, integration, vendor, AI provider, or offline
  design exposes a missing constitutional dependency.

- A court order, law, regulation, professional duty, welfare
  requirement, or safeguarding obligation changes the governing
  hierarchy.
