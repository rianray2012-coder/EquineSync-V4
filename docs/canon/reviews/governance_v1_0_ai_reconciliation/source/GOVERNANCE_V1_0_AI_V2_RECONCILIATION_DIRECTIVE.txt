# CODEX DIRECTIVE

## AI V2.0 RECONCILIATION, GOVERNANCE CLOSURE ASSESSMENT, AND GOVERNANCE V1.0 CONSTITUTIONAL BASELINE ADOPTION AND LOCK

### 1. DIRECTIVE STATUS

This directive authorizes a controlled, multi-phase constitutional-governance reconciliation and closure process for EquineSync.

The authorized work includes:

1. Completion of the exact-source, checksum, adoption, and lock reconciliation for the EquineSync AI Governance V2.0 constitutional canon.
2. Recovery and controlled reconciliation of the exact companion governance artifacts identified in this directive.
3. Formal constitutional integrity, dependency, traceability, ownership, authority, identifier, and cross-reference scans.
4. Closure or controlled disposition of governance-level P2 dependencies required for the final constitutional baseline lock.
5. Completion of the final Governance Closure Assessment.
6. Preparation and issuance of the Governance V1.0 Constitutional Baseline Adoption and Lock Package.

This directive does not authorize:

* production deployment;
* runtime activation;
* code implementation;
* infrastructure mutation;
* database or schema mutation;
* migration execution;
* external-provider activation;
* AI-provider activation;
* model configuration changes;
* training or fine-tuning activity;
* processing of live customer data;
* secrets or credential changes;
* public launch;
* public trust, compliance, certification, or security claims;
* silent amendment of founder-approved decisions;
* substitution of reconstructed language for an exact source where exact source recovery remains possible;
* adoption of any artifact that fails the required constitutional integrity gates.

All work must remain repository-local, evidence-preserving, non-destructive, and governance-only unless a later founder directive expressly grants broader authority.

---

# 2. GOVERNING OBJECTIVE

The objective is to establish a complete, evidence-backed, internally consistent, founder-controlled constitutional baseline for EquineSync Governance V1.0.

The final baseline must demonstrate that:

1. every controlling constitutional canon included in the baseline has an identified source, authority state, adoption state, and lock state;
2. every required source has either been exactly recovered or given an explicit evidence classification;
3. every controlling file has a verified checksum;
4. every founder decision is traceable to the controlling canon or companion artifact that implements it;
5. every governance requirement is mapped to an authoritative source and an accountable authority owner;
6. all cross-canon references resolve correctly;
7. no unresolved blocking dependency, orphan requirement, duplicate identifier, authority ambiguity, or material dependency cycle remains;
8. governance-level P2 dependencies required for baseline lock have been closed, incorporated, superseded, or explicitly determined not to block the baseline;
9. the final package distinguishes constitutional adoption and lock from implementation or production authority;
10. the resulting baseline can function as the controlled source of truth for subsequent implementation waves and specialized governance work.

# 3. CONTROLLING BASELINE AND EVIDENCE PRINCIPLES

Codex must begin from the most recent founder-approved constitutional source-reconciliation baseline and must preserve all prior approved findings unless new exact evidence proves that a correction is required.

The following rules apply throughout all phases:

## 3.1 Evidence hierarchy

Use the following hierarchy, from strongest to weakest:

1. exact repository bytes at an authoritative path;
2. exact mounted source bytes with independently verified checksum;
3. exact checksum-bearing adoption or lock package;
4. exact founder-approved source located in the File Library or supplied evidence package;
5. exact quoted source language preserved in a founder directive or controlled decision ledger;
6. corroborated derivative artifact that identifies the exact controlling source;
7. reconstructed or inferred content.

Reconstructed or inferred content may be used only for diagnostic comparison. It may not be represented as an exact recovered source.

## 3.2 No silent reconstruction

If an exact artifact cannot be recovered:

* do not silently regenerate it;
* do not overwrite an existing artifact with a reconstruction;
* do not label reconstructed text as exact;
* assign an evidence classification;
* identify the missing evidence;
* determine whether the absence blocks adoption or lock;
* create a founder-review item only where founder action is actually required.

## 3.3 Founder-approved language

Founder-approved language must be preserved exactly except for:

* purely mechanical formatting normalization;
* correction of an objectively provable typographical error that does not alter substance;
* normalization expressly authorized by an existing founder decision;
* cross-reference repair that does not alter the underlying policy.

Any substantive conflict must be escalated and must not be resolved through Codex inference.

## 3.4 Immutable prior locks

Previously locked artifacts must not be modified in place.

Where correction is required:

* preserve the locked artifact;
* create a superseding version or controlled reconciliation record;
* document the relationship between the locked source and the superseding artifact;
* state whether the prior lock remains historically valid, is superseded prospectively, or contains a documented non-substantive defect.

## 3.5 Hashing

Use SHA-256 for every artifact included in the adoption and lock package.

Hash:

* the exact source artifact;
* any adoption record;
* any lock record;
* each final companion artifact;
* the machine-readable baseline manifest;
* the final package archive, if one is created.

Record file size, canonical repository path, hash, source classification, authority classification, adoption state, lock state, and verification timestamp.

# 7. SEVERITY AND CLOSURE RULES

Use the following governance severity model:

## P0

A defect that invalidates constitutional authority, creates a material safety or legal contradiction, corrupts source integrity, or makes the baseline untrustworthy.

P0 must be zero before adoption or lock.

## P1

A material governance defect that prevents reliable constitutional interpretation, authority assignment, traceability, or enforcement.

P1 must be zero before adoption or lock.

## P2

A bounded defect, incompleteness, or follow-up that does not invalidate constitutional meaning.

A P2 may remain after lock only if it is expressly classified as nonblocking and does not affect:

* controlling policy;
* founder intent;
* authority ownership;
* source integrity;
* checksum integrity;
* requirement completeness;
* cross-reference resolution;
* safeguarding;
* equine welfare;
* legal, financial, medical, privacy, or security boundaries;
* adoption or lock validity.

## P3

Editorial or convenience improvement with no constitutional effect.

P3 items may be retained without affecting the lock.
