# 1. Purpose

This Index answers the operational constitutional question: Where is
this subject governed, and what else must be read with it? It provides a
topic-to-canon index, a canon-to-topic reverse index, and consolidated
reading sets for high-risk cross-domain matters.

The Index is navigational. It does not independently create, expand,
narrow, adopt, lock, implement, or supersede substantive constitutional
authority. The controlling version and lifecycle posture of each
referenced family must be resolved through the Controlled Canon Index,
founder evidence, and applicable lock or implementation records.

# 2. Governing Cross-Reference Rules

- Start with the identified primary canon, then read every companion
  canon needed for the actual facts and risk.

- A cross-reference does not transfer subject-matter ownership from the
  primary canon to a supporting canon.

- A specialized overlay, including AI, reporting, media, search, plugin,
  security, or operations governance, controls its layer but does not
  replace the underlying legal, financial, welfare, relationship,
  permission, or record authority.

- The more protective compatible privacy, safeguarding, security,
  welfare, evidentiary, or permission rule applies.

- A filename, schema field, route, user-interface label, provider
  feature, or existing code path is not constitutional authority.

- Where ambiguity materially affects safety, welfare, minors, privacy,
  legal rights, ownership, finance, evidence, retention, or access, work
  must pause for controlled reconciliation.

- Version suffixes are not proof of adoption, lock, implementation
  authority, production authority, or public-launch authority.  
  Founder-designated exception: the Security Foundational Models V1.0
  package controls within its reconciled scope until expressly
  superseded, notwithstanding higher-numbered references elsewhere.

# 3. How to Use This Index

1.  Locate the closest topic in Section 5 or use the consolidated
    reading sets in Section 7.

2.  Begin with the Start With canon family.

3.  Review all Read With families that are relevant to the facts, actor,
    data, horse, facility, payment, workflow, or risk.

4.  Open the linked Authority Matrix entry to confirm ownership and the
    anti-drift boundary.

5.  Resolve the active version and lifecycle status through the
    Controlled Canon Index and Founder Decision Register.

6.  Use the Vocabulary and Definitions Index for controlling meanings
    and aliases.

# 4. Field Guide

- XREF ID: stable locator for this Index.

- Topic / Common Search Terms: the subject a reader is trying to govern
  or locate.

- Start With: the primary constitutional owner for the subject.

- Read With: principal supporting, boundary, evidence, or overlay
  authorities.

- Authority Matrix: the corresponding ownership and precedence entry.

# 9. Version and Lifecycle Resolution

This Index uses constitutional family titles rather than treating a
particular filename or version suffix as permanently controlling. The
Controlled Canon Index and Founder Decision Register must resolve the
active substantive successor, lifecycle status, effective scope,
checksum, and authority posture. A later draft does not displace an
adopted or locked canon merely because its version number is higher.

# 10. Maintenance Triggers

Update this Index when a new constitutional family is created, a
successor is founder accepted, a canon is renamed, a domain boundary
changes, a cross-canon conflict is reconciled, an Authority Matrix row
is added or reassigned, an implementation RF identifies an unindexed
subject, or a frequently used search term fails to route readers to the
correct authority. Preserve prior versions and record additions,
removals, retitled subjects, changed reading sets, and unresolved
references.
