# Identity, Account, and Actor V2.0 Core Distinctions Verification Matrix

| Distinction | Candidate rule | Result |
| --- | --- | --- |
| Person vs account | A person may exist without an account; account is an access container | Pass |
| Account vs credential | Account associates methods/sessions; credential is authentication evidence | Pass |
| Actor vs role | Actor is attributed doer; role is separately governed input | Pass |
| Actor vs permission | Actor identity supplies context; Permission decides access | Pass |
| Identity vs authentication | Durable identity is independent of presented authentication evidence | Pass |
| Identity vs authorization | Verification/login never grants authorization | Pass |
| Identity vs relationship | Identity supplies endpoints; Relationship creates/governs relationship objects | Pass |
| Identity vs representation | Identity supplies parties/context; Relationship/Agreement govern representation | Pass |
| Representation vs capacity | Identity does not establish legal capacity or agreement effect | Pass |
| Delegation vs ownership | Delegation is scoped external authority; it does not create ownership | Pass |
| External evidence vs canonical identity | Provider evidence maps through replaceable adapters and cannot become authority alone | Pass |
| Human vs system actor | System/service/integration actors are distinct and attributable | Pass |
| Automated actor vs AI authority | AI actor identity/attribution does not grant autonomy or human authority | Pass |

No account, credential, session, device, authentication, payment, signature, provider event, role, or profile creation independently establishes legal, relational, financial, contractual, or permission authority.
