# External Architecture V2.0 Required Corrections and Expansions

## Required before controlled adoption: completed

### EA-C01: Provider direction disclaimer

Rename “Approved first-provider set” to “Proposed first-provider direction pending separate founder and readiness authorization.” Add an exact rule that naming a provider does not approve procurement, credentials, configuration, coding, activation, data transfer, production use, or vendor-specific RF execution.

### EA-C02: Provider-neutral RF contracts

Rewrite RF33-RF36 dependencies around capabilities and adapter contracts. Named vendors may remain illustrative candidates, but each RF must require a separate vendor decision and preserve replacement without constitutional change.

### EA-C03: Historical provenance correction

Remove claims that Version 1 was completely reviewed or preserved. Reference the Historical Provenance Exception Ledger and state that available principles were preserved from evidenced sources while predecessor completeness cannot be proven.

### EA-C04: State-qualified canon references

Label Identity, Agreement, Audit, Communications, Financial Truth, Platform Operations, and other unsettled sources by their actual governed state. A dependency reference must not imply adoption or lock.

EA-C01 through EA-C04 were completed under the founder `ACCEPT_WITH_MODIFICATION` decision. See `EXTERNAL_ARCHITECTURE_V2_0_FOUNDER_DECISION_AND_CORRECTION_REPORT.md` for the checksum-backed correction trace.

## Recommended expansion before lock

### EA-E01: Unified external event provenance envelope

Consolidate the scattered provenance requirements into one minimum envelope: provider, provider account/environment, provider event ID, source timestamp, receipt timestamp, request ID, correlation ID, causation ID, actor, adapter and contract versions, signature-validation result, replay/idempotency key, raw-evidence reference, canonical mapping result, audit reference, and reconciliation state.

### EA-E02: Constitutional truth-state vocabulary

Define provider, transport, synchronization, implementation, and canonical domain states as separate vocabularies with prohibited equivalences.

### EA-E03: Founder decision ledger

Normalize the two founder-decision lists into a versioned ledger with decision owner, dependencies, risk, disposition, deferral reason, evidence, and authority effect. Decisions about providers must remain separate from constitutional adoption.

### EA-E04: Independent legal, privacy, security, and financial review triggers

Define which vendor/data/criticality classes require specialist review before sandbox, staging, or production approval. This requirement must not imply that any review or activation has occurred.
