## 2. Executive Summary

EquineSync requires a visual system that feels premium, calm, horse-centered, technologically capable, and immediately usable in real barn conditions. The system shall create recognition without allowing decoration to obscure care work, permissions, safety, search scope, operational status, or accessibility.

The approved identity hierarchy is:

1. **Full EquineSync logo or wordmark lockup:** formal identification where the name must be read.
2. **Circuit-horse mark:** primary product mark and primary production app icon.
3. **9D Circle Monogram:** secondary compact mark and approved optional alternate app icon.
4. **9C Speed Lines Mark:** ultra-small favicon and constrained system mark.
5. **EquineSync Steed:** source-supported provisional name for the mascot and controlled product-delight layer. The spelling conflict with recent `Stead` usage remains open for Founder confirmation.

The approved typography hierarchy is:

1. **Bright Demo:** expressive brand headlines and hero statements.
2. **Bodoni Moda:** `In Sync.` and short premium signature moments.
3. **Lora:** body, editorial, educational, documentation, and spacious product copy.
4. **Operational utility typeface:** unresolved; Inter remains the recommended Founder decision for navigation, controls, tables, calendars, search, badges, timestamps, and dense mobile interfaces.

The required static brand system is a first-release dependency. Mascot animation, hidden easter eggs, seasonal treatments, and optional alternate icons are separately gated enhancements and may remain disabled without blocking otherwise qualified enrollment.

## 6. Definitions and Controlled Vocabulary

- **Application Shell:** Persistent frame containing navigation, active context, search entry points, account controls, status surfaces, and shared patterns.
- **Brand Token:** Registered semantic design value used through a controlled token rather than local hard-coded styling.
- **Formal Brand Identity:** Full EquineSync name lockup and approved corporate/product marks.
- **Circuit-Horse Mark:** Horse silhouette with circuit and motion elements; primary product mark and default app-icon concept.
- **9D Circle Monogram:** Compact `E-S` monogram inside a circle; secondary compact mark and approved optional alternate app icon.
- **9C Speed Lines Mark:** Ultra-minimal speed-line mark forming an `E`-like structure; ultra-small favicon and constrained system mark.
- **EquineSync Steed:** Source-supported provisional mascot term. `Stead` is a recent alternate spelling that is not canonical until Founder decision.
- **Serious Workflow:** Injury, emergency, medication error, missed critical care, safeguarding, abuse or neglect, legal execution, payment dispute or failure, account suspension, security/privacy incident, outage, emergency evacuation, severe weather, evidence preservation, or another high-consequence workflow.
- **Optical Simplification:** Approved detail reduction for small-size clarity without creating a new identity.
- **Alternate App Icon:** User-selected cosmetic icon that does not change account, role, plan, facility, permission, environment, or product state.
- **Easter Egg:** Optional low-frequency interaction that never gates information, rights, or workflow completion.
- **Campaign Color:** Color permitted only in an approved mascot, campaign, seasonal, or promotional asset and not as an ordinary shell token.
- **As-Designed / As-Built / As-Verified:** Approved documentary baseline; implemented state; and tested evidence-backed state.

## 9. User and Operational Workflows

### `NAV-WF-001` Responsive identity selection

1. Determine platform, surface, theme, rendered size, interaction role, and mask behavior.
2. Resolve the approved asset through the asset manifest.
3. Select full logo, circuit horse, 9D, or 9C according to the registered surface rule.
4. Apply accessible naming only when interactive or informative.
5. Render from a registered derivative.
6. On failure, use the registered fallback and emit an observable event.

### `NAV-WF-002` Application icon build

1. Retrieve registered circuit-horse master and platform derivative rules.
2. Generate Apple and Android platform assets using then-current official requirements.
3. Preserve the horse identity across default, dark, clear/tinted, adaptive, themed, monochrome, legacy, notification, and store variants as applicable.
4. Preview masks and appearances.
5. Record checksums and render evidence.
6. Block release on clipping, identity drift, or unregistered derivatives.

### `NAV-WF-003` Optional 9D alternate icon

1. Show only packaged, registered alternate icons.
2. Explain that the change is cosmetic.
3. Apply through the supported platform mechanism.
4. Preserve all account and product state.
5. Record only the minimum preference state required.
6. Permit restoration of the default circuit horse.

### `NAV-WF-004` Mascot eligibility

1. Classify the current workflow as ordinary, elevated, or serious.
2. Check role, age/guardian context, active tenant/context, feature flag, user motion preference, frequency state, and asset availability.
3. If any required check is unknown, suppress the mascot.
4. Select only an allowlisted state and approved copy.
5. Render a static fallback for Reduced or Off mode as applicable.
6. Do not alter workflow outcome.

### `NAV-WF-005` Search no-result state

1. Execute permission filtering before presentation.
2. Determine whether the result is `NO_AUTHORIZED_MATCH`, `OFFLINE_DATA_UNAVAILABLE`, `INDEX_UNAVAILABLE`, or `QUERY_INVALID`.
3. Show accurate neutral guidance.
4. Use a mascot only for ordinary low-risk states and only when enabled.
5. Do not imply that hidden records exist or that the system searched beyond the user’s authority.

### `NAV-WF-006` Superseded asset correction

1. Detect a superseded or unregistered active asset.
2. Freeze promotion of the affected build.
3. identify every surface and cache using the asset.
4. Deploy the registered replacement through controlled rollout.
5. invalidate caches where required;
6. preserve before/after evidence and rollback capability.

## 15. User Interface and Experience Requirements

### 15.1 Brand character

The shell shall feel calm, capable, refined, human, horse-centered, and technologically precise. It shall avoid rustic ranch tropes, excessive gradients/noise, childish purple, generic SaaS blue, decorative clutter, and novelty horse imagery.

### 15.2 Color system

**Primary structural tokens:** Midnight Graphite, Slate Navy, Frost White, Platinum Mist.  
**Supporting accents:** Smoky Lilac, Frosted Lavender Gray, Ice Blue, Glacier Silver Blue.  
**Semantic status colors:** Separately registered and tested; not inferred solely from brand colors.  
**Campaign-only yellow:** Not an ordinary shell token.

### 15.3 Typography

- Bright Demo: hero and high-space brand statements only.
- Bodoni Moda: `In Sync.` and brief premium signature moments.
- Lora: body/editorial/documentation/spacious product content.
- Utility face: compact operational UI after Founder decision.
- Immutable logo artwork shall not be reconstructed from live fonts unless the production lockup specification expressly requires it.

### 15.4 Logo and mark placement

- Use the full registered lockup when the name must be read.
- Use circuit horse for primary product identification and default app icon.
- Use 9D for compact identity and optional alternate icon.
- Use 9C for ultra-small registered surfaces.
- Preserve proportions, direction, circuit details, and clear space.
- Do not stretch, skew, rotate, mirror, crop essential features, add unapproved effects, or combine with unrelated horse art.

### 15.5 Mascot state/context matrix

| State | Allowed examples | Prohibited or caution |
|---|---|---|
| Default | Welcome, ordinary empty state, help | No serious workflow status |
| Blink | Calm idle, nothing-new, completed ordinary care | Not proof of system health or safety |
| Canter left/right | Non-sensitive loading, onboarding transition, schedule/timeline load | Not failed sync, emergency, or unknown status |
| Jump | Ordinary task completion, first horse, low-risk onboarding, facility ticket closed | No legal signing, payment approval, injury, medication error, or safety event |
| Head tilt | Missing optional information, ordinary empty state, missing gear | Not urgent injury, safeguarding, or high-risk medical uncertainty |
| Thinking | Ordinary search/report preparation or recommendation draft | Not authoritative clinical/legal/financial judgment |
| Time check | Routine upcoming or overdue item | Not the sole urgent or missed-medication signal |
| Wave | Welcome, ordinary update, invitation accepted | Not private communication encouragement for minors |
| Out of gas | End of long setup or non-serious end-of-day moment | Never outage, billing failure, incident, or medical emergency |

### 15.6 Approved hidden moments, all flag-gated

- five taps/clicks: tiny jump and `You found the Steed`;
- idle corner peek after 60 to 90 seconds, no more than once per 30 minutes;
- late-night quiet-hours message without muting urgent alerts;
- tack-room peek;
- whiteboard doodle after all urgent items are genuinely cleared;
- facility-ticket completion after evidence is recorded;
- missing/found gear nudge; and
- desktop hover after two seconds.

No badge may affect access, pricing, ranking, or operations.

### 15.7 Serious-workflow exclusion register

Mascot animation, playful copy, Bright Demo, and decorative premium moments are prohibited in:

- horse, rider, staff, or visitor injury;
- urgent body check or welfare concern;
- medication error or missed critical medication;
- emergency veterinary authorization;
- safeguarding, Safe Sport, abuse, neglect, or minor-protection warning;
- legal document execution, formal notice, evidence preservation, or legal hold;
- payment failure, dispute, suspension, collection, refund dispute, or account suspension;
- security/privacy incident or breach;
- platform outage, failed critical sync, disaster recovery, or severe weather emergency;
- evacuation, escaped-horse emergency, fire, utility failure, or another urgent event.

### 15.8 Accessible behavior

- Interactive identity controls shall expose one accessible name: `EquineSync` or the actual action label.
- Decorative assets shall be ignored by assistive technology.
- Text shall remain text where essential.
- Keyboard, screen reader, zoom, dynamic text, orientation, reflow, focus, and contrast shall be tested.
- Full, Reduced, and Off motion settings shall preserve equivalent meaning.
- Primary barn-operation targets shall be at least 44 by 44 CSS pixels/points.

## 31. Golden-Path Reproduction Scenarios

### `NAV-GP-001` First launch and sign-in

A new authorized user installs EquineSync, sees the circuit-horse default icon, opens a restrained accessible sign-in surface, and enters the role-appropriate shell. Evidence captures platform icon, lockup, typography, focus, contrast, theme, and asset versions.

The user collapses navigation. The full lockup changes to the approved compact mark, retains one accessible name, preserves focus/order, and does not change context or authority.

### `NAV-GP-003` Permission-safe no-result search

An authorized user searches within the active context and receives `NO_AUTHORIZED_MATCH`. Neutral guidance appears. Optional mascot remains static/eligible only if enabled and does not imply protected records.

### `NAV-GP-004` Offline barn operation

A user launches under poor connectivity. Bundled assets, typography fallbacks, active context, and accurate offline state render. A stale revoked asset does not return. Essential work remains legible.

### `NAV-GP-005` Optional 9D alternate icon

An eligible user selects 9D. The system uses the supported platform mechanism, retains all account and tenant state, and restores the default on request.

### `NAV-GP-006` Ordinary mascot completion

With flags enabled and Full motion selected, an eligible ordinary task completion displays a brief approved state within frequency limits. The task result exists independently and remains identical in Reduced and Off modes.

### `NAV-GP-007` Serious workflow suppression

A user enters an injury or safeguarding workflow. The shell uses formal restrained identity, direct language, and accessible controls. Mascot and playful display treatment remain absent even if global flags are enabled.

### `NAV-GP-008` First-user enrollment relevance

A first external user completes sign-in and onboarding with the required static brand system, accessible shell, correct platform assets, and no optional mascot dependency. The scenario proves that optional delight can remain OFF without blocking enrollment.
