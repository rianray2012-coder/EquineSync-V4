# EQUINESYNC FOUNDER DIRECTIVE

## PHASE 1 FOUNDER-ORCHESTRATED REVIEW OPERATING MODEL

### Procedurally Segregated Internal AI Review

You are operating in the official EquineSync repository.

This directive establishes the first phase of a controlled three-phase program to resolve the present inability to reliably select and invoke the eight approved Founder-Orchestrated Review Agents through the current Codex runtime.

This is the initial and controlling directive for this program. No prior three-phase implementation directive has been issued or should be assumed.

---

# 1. STRENGTHENED THREE-PHASE PLAN

The Founder adopts the following phased direction:

## Phase 1

### Manual Procedurally Segregated Review

Establish a defensible operating model that allows the eight Founder-approved review roles to function through:

* versioned role configurations;
* fresh and isolated executions;
* blind parallel review where appropriate;
* bounded and role-specific inputs;
* read-only frozen candidates;
* deterministic machine validation;
* controlled evidence custody;
* accurate assurance classifications;
* explicit Founder oversight and decision authority.

Phase 1 is intended to remove the immediate dependency on unsupported runtime-native agent selection.

## Phase 2

### Founder Review Orchestrator

After Phase 1 is validated and expressly approved by the Founder, build a controlled orchestration utility that automates the approved Phase 1 process through separate provider requests, strict context boundaries, evidence ledgers, schemas, validation controls, and Founder decision handoffs.

Phase 2 is not authorized by this directive.

## Phase 3

### MIAP Integration

After Phase 2 is separately authorized, implemented, validated, adversarially reviewed, and approved by the Founder, design and implement controlled integration with the Master Implementation Atlas Program.

Phase 3 is not authorized by this directive.

## Mandatory phase gates

Phase 2 may begin only after:

1. Phase 1 is completed;
2. Phase 1 validation passes;
3. all Phase 1 blockers and limitations are disclosed;
4. the Founder reviews the Phase 1 evidence package; and
5. the Founder expressly authorizes Phase 2.

Phase 3 may begin only after:

1. Phase 2 is separately authorized;
2. the Phase 2 prototype is completed;
3. technical, security, adversarial, and evidence validation pass;
4. the Founder approves the Phase 2 technical baseline; and
5. the Founder expressly authorizes Phase 3.

Do not infer authorization from the completion, approval, or existence of an earlier phase.
